# 🖼️ Image Service

## 🚀 `ImageService` – функциональная возможность
🔹 **Управление изображениями**  
🔹 **Предоставление публичных ссылок** для `ProductService`  
🔹 **Хранение изображений в облачном хранилище** (MinIO)

---

## 📌 Требования к сервису

1️⃣ **Запросы на управление изображениями** отправляются в этот сервис.  
2️⃣ **Связь с `ProductService`**:
- Система знает **минимальную информацию о продукте**, который создается в `ProductService`.
- При удалении продукта в `ProductService` этот сервис также **удаляет связанные данные**.
- Сервис **подписывается на события** создания/удаления продукта через `Kafka`.  
  3️⃣ **Хранение изображений**:
- Клиент загружает изображение – оно сохраняется в **облачном хранилище (MinIO)**.  
  4️⃣ **Доступ к изображениям**:
- Изображения доступны через **публичные ссылки**, созданные хранилищем.  
  5️⃣ **События обновления**:
- При **добавлении/удалении** изображения сервис **уведомляет `ProductService`** через `Kafka`.

---

## ⚙️ Основные функции

### 1️⃣ Добавление нового изображения для продукта
📌 **Процесс**:
1. Сохраняет изображение в **облачное хранилище**.
2. Добавляет запись об изображении в **базу данных**.
3. Уведомляет `ProductService` о **новом изображении** продукта.

📥 **Необходимые данные**:
- 🆔 `UUID` продукта, для которого добавляется изображение.
- 📂 Файл изображения (`file`).
    - ✅ **Максимальный размер**: `5 МБ`.
    - ✅ **Допустимые форматы**: `JPG, PNG`.

---

### 2️⃣ Удаление существующего изображения
📌 **Процесс**:
1. Удаляет изображение из **облачного хранилища**.
2. Удаляет запись об изображении из **базы данных**.
3. Уведомляет `ProductService` о **удалении изображения**.

📥 **Необходимые данные**:
- 🆔 `UUID` изображения, которое нужно удалить.

---

## 🎯 Дополнительные функции

### 🔔 Уведомления от `ProductService`:
- 📢 **О добавлении нового изображения**.
- 📢 **О удалении изображения**.

### 🔄 Получение событий от `ProductService`:
- ✅ **Создание продукта** → Система сохраняет `UUID` нового продукта.
- ❌ **Удаление продукта** → Система удаляет продукт и **все связанные изображения**:
    - 🗂️ **Из базы данных**.
    - ☁️ **Из облачного хранилища**.

# 🖼️ Image Service – Cущности и Use Case

## 📌 Примерный вариант сущностей

### 🔹 `ImageService`
- Должен знать **минимальную информацию** о продуктах.
- **Не хранит** ссылку на изображение – эта информация передается клиенту вместе с данными о продукте.

### 📦 `Product` (Минимальная информация о продукте)
| Поле    | Тип данных | Описание               |
|---------|------------|------------------------|
| 🆔 `id` | `UUID`     | Идентификатор продукта |

### 🖼️ `Image` (Изображение)
| Поле           | Тип данных | Описание                  |
|----------------|------------|---------------------------|
| 🆔 `id`        | `UUID`     | Идентификатор изображения |
| 🔗 `productId` | `UUID`     | Внешний ключ на `Product` |

---

## 🛠️ USE CASE

### 📤 Добавление нового изображения для продукта
1️⃣ **Клиент отправляет запрос**, содержащий:
- 🆔 `UUID` продукта.
- 📂 Файл изображения.

2️⃣ **Валидация изображения**:
- ✅ Размер файла **не больше 5 МБ**.
- ✅ Допустимые форматы: **JPG, PNG**.

3️⃣ **Проверка существования продукта**:
- Если `UUID` продукта **не найден** в системе → ❌ возвращаем ошибку клиенту.

4️⃣ **Создание нового изображения в системе**.  
5️⃣ **Добавляем изображения в облако** (`MinIO`).  
6️⃣ **Сохраняем изображения в базе данных** с сгенерированным `UUID`.  
7️⃣ **Возвращаем успех клиенту**.  
8️⃣ **Уведомляем `ProductService` о новом изображении**.

---

## ☁️ Добавление изображения в `MinIO`
1️⃣ **Загрузка изображения** в `MinIO` под заранее сгенерированным `UUID`.  
2️⃣ **После успешной загрузки** `MinIO` возвращает **публичную ссылку** на изображение.
- ❌ Если загрузка не удалась → генерируется **исключение** и возвращается **ошибка**.

---

## 🔄 Отправка события в `ProductService` (Kafka)
📢 **После успешного добавления** фото в облако и БД:  
1️⃣ Создаем **событие в `Kafka`** (`topic: image-create`).  
2️⃣ `ProductService` подписывается на это событие.  
3️⃣ Отправляем в `Kafka` данные об изображении:
- 🆔 `UUID` изображения.
- 🆔 `UUID` продукта.
- 🌍 `String` публичная ссылка на изображение.

---


# 🖼 Удаление изображения продукта из системы

## 📌 Описание процесса
Процесс удаления изображения продукта включает несколько этапов:

1. 🔹 **Получение запроса**
    - Клиент отправляет запрос на удаление изображения продукта, передавая `UUID` изображения.
    - Если изображение не найдено в системе, возвращается ошибка.

2. 🗃 **Удаляем изображение из базы данных**

3. ✅ **Ответ клиенту**
    - Клиенту отправляется подтверждение успешного удаления.

4. ☁ **Удаление из облака**
    - Физическое удаление изображения из облачного хранилища.

5. 🔔 **Отправка события**
    - Система отправляет событие об удалении изображения для продукта (например, через систему сообщений или брокер событий).  

# 🖼 Удаление изображения из облака (Minio в фоновом режиме)

## 🔹 Основной процесс
1. 🗑 **Удаляем изображение из Minio**, указывая `UUID`, под которым оно хранится.
    - ❌ **Если произошла ошибка то…**

---

## 🔍 Анализ проблемы
Мы можем удалить изображение из базы данных, но если сначала удалять из облака, сервис будет перегружен, а клиенты — ждать слишком долго.  
Однако, если изображение удаляется из базы, но не из Minio, оно может остаться в облаке.

---

## 💡 Решение
1. **Запуск периодической фоновой задачи**, которая будет удалять изображения, удалённые из базы, но оставшиеся в облаке.
2. **Фоновая задача должна понимать, какие изображения удалены из базы, а какие — нет**.
    - При удалении из базы **только отмечаем** их как удалённые (`status = deleted`).
3. **Удаляем из базы только после успешного удаления из облака**.
4. **Изменяем алгоритм удаления** + добавляем новые данные в сущность `Image`.

---

## 🚀 Оптимизированный алгоритм удаления продукта
### 1️⃣ Основное удаление
1. **Помечаем фото как удалённое** (`status = deleted`).
2. **Уведомляем сервис продуктов** об удалении изображения.
3. ✅ **Операция завершена**.

### 2️⃣ Фоновая задача
1. **Запускаем фоновую задачу**, которая удаляет изображения из Minio.
2. **Находит изображения со статусом `deleted`**.
3. **Пробует удалить каждое из Minio**.
    - 🟢 **Если удаление успешно** → также удаляем из базы.
4. 🔄 **Процесс повторяется до полного удаления**.  

## Удаление существующего изображения из системы (обновленная версия)

1. **Получаем запрос** на удаление изображения.
2. **Отмечаем изображение удаленным** в базе данных.
3. **Отправляем клиенту успешный ответ**.
4. **Запускаем фоновую задачу для удаление изображение из базы данных и из облака**.
5. **Отправляем событие об удалении изображения** для продукта.

---

## Отправка события об удалении изображения для продукта *(Kafka, асинхронно)*

1. **После удаления изображения из системы**.
2. **Создаем событие**, чтобы уведомить `Product` сервис об удалении изображения *(topic: `image-deleted`)*.
3. **Подписываем `Product` сервис** на это событие.
4. **Отправляем UUID изображения**, которое было удалено из системы.  


# Обработки событий от `Product` сервиса

## 1. Получение уведомлений от `Product` сервиса
Система подписывается на два события, отправляемые `Product` сервисом:
1. **При создании продукта**
2. **При удалении продукта**

---

## 2. Событие: создание продукта
1. **Система получает уведомление** о создании продукта.
    - Получаем минимальные данные (`UUID` созданного продукта).
2. **Создаем новую сущность продукта** в системе с переданным `UUID`.
3. **Сохраняем продукт в базе данных**.

---

## 3. Событие: удаление продукта
1. **Система получает уведомление** об удалении продукта.
    - Получаем `UUID` удаленного продукта.
2. **Удаляем продукт из базы данных**.
3. **Удаляем все связанные изображения**:
    - Из базы данных.
    - Из облачного хранилища *(логика удаления изображений уже описана выше, повторять нет смысла)*.

---

## 4. После проектирование примерно сущности выглядят так:

### `Product`
| Поле   | Тип    | Описание                           |
|--------|--------|------------------------------------|
| `id`   | `UUID` | Уникальный идентификатор продукта  |

### `Image` (Изображение)
| Поле         | Тип    | Описание                                 |
|--------------|--------|------------------------------------------|
| `id`         | `UUID` | Уникальный идентификатор изображения     |
| `productId`  | `UUID` | Внешний ключ на `Product`                |
| `status`     | `enum` | Статус изображения (`ACTIVE`, `DELETED`) |
